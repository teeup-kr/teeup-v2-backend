# 팀 편성 전체 케이스 가이드

## 1. 개요

### 1.1 목적

이 문서는 팀 편성 기능의 **모든 경우의 수(48케이스)** 를 한곳에 정의하고, 실제로 **몇 명을 어떤 조건으로 받아 팀 편성을 어떻게 진행하면** 전 케이스를 검증할 수 있는지 정리한 가이드입니다.

### 1.2 전제 조건

- **Google 계정 30개 이상 생성이 불가**한 환경을 전제로 합니다.
- 따라서 **스크립트로 mock 사용자(User, Provider.LOCAL)** 를 생성해 사용하는 흐름이 필수입니다.
- 48개 모임 × 최대 20명을 실인물로 채우는 것은 비현실적이므로, **mock 사용자 풀(30명)** 을 한 번 만들고 동일 클럽·동일 풀에서 참가자만 다르게 배정해 재사용합니다.

### 1.3 문서에서 다루는 범위

- **편성 모드**: 6종 (성별 분리/혼합 × 핸디캡/직전대회성적/랜덤)
- **인원수**: 4명 ~ 20명 (나머지 0, 1, 2, 3 케이스 포함)
- **팀 크기**: 기본 4명(4인조 기준). 2인조·3인조는 UI에서 선택 가능하며, 본 가이드의 예상 팀 구성은 **팀 크기 4** 기준입니다.

## 3. Mock 사용자 전략 (Google 계정 불필요)

### 3.1 사용 스크립트

- **파일**: `apps/backend/scripts/create_test_users.py`
- **실행**: `cd apps/backend && python scripts/create_test_users.py`

### 3.2 생성되는 사용자

| 항목 | 내용 |
|------|------|
| 인원 | **30명** |
| 로그인 방식 | `Provider.LOCAL` (Google/OAuth 불필요) |
| 이메일 | `user1@teeup.run` ~ `user30@teeup.run` |
| 공통 비밀번호 | `test1234` |
| 성별 | 남성 약 18명, 여성 약 12명 (TEST_USERS_DATA 기준) |
| 핸디캡/평균타수 | 0~68, 평균타수 68~140 등 다양하게 설정됨 |

### 3.3 왜 30명이면 충분한가

- **단일 모임 최대 인원**: 20명 (케이스 47, 48).
- **성별 분리 최대 요구**: 20명일 때 남10 / 여10 → 남성 10명 이상, 여성 10명 이상 필요.
- 현재 구성(남 약 18, 여 약 12)이면 **한 모임 기준으로는 항상 충분**합니다.
- **48개 모임**은 동일 클럽·동일 사용자 풀에서 **참가자만 다르게 배정**하면 되므로, 한 번 만든 30명을 여러 모임에 **재사용**합니다. (한 사람이 여러 모임에 참가 가능)

### 3.4 최소 요구 사항

- **최소 인원**: 30명 (남 10명 이상, 여 10명 이상 권장).
- **클럽 가입**: `create_test_users.py` 실행 후, 이 30명을 테스트용 클럽에 가입시키는 단계가 필요합니다. 기존 `batch_join_club.py` 또는 동일 목적 스크립트를 활용하세요.

## 4. 실행 절차 (스크립트 순서)

아래 순서대로 진행하면 48케이스 전부에 대해 "참가자 확보 → 팀 편성 가능 상태"까지 만들 수 있습니다.

### 4.1 1단계: Mock 사용자 생성

```bash
cd apps/backend
python scripts/create_test_users.py
```

- **결과**: user1@teeup.run ~ user30@teeup.run, 공통 비밀번호 test1234, Provider.LOCAL.

### 4.2 2단계: 클럽 준비

- 테스트용 **클럽 1개**가 존재하는지 확인합니다.
- `create_test_meetings.py`는 기본적으로 클럽 `display_id = "cmiy6k1oe0001ldau4p"` 를 사용합니다. 환경에 맞게 스크립트 내 `club_display_id` 를 수정하거나, 해당 display_id 를 가진 클럽을 준비합니다.
- **30명 전원**을 해당 클럽에 가입시킵니다. (예: `batch_join_club.py` 또는 동일 목적 스크립트 사용)

### 4.3 3단계: 48개 모임 생성

```bash
cd apps/backend
python scripts/create_test_meetings.py
```

- 동일 클럽에 **48개 라운딩 모임**이 생성됩니다.
- 각 모임의 `team_formation_mode`, `max_participants` 는 `create_test_meetings.py` 의 `MEETING_CONFIGS` 와 동일합니다 (위 §2와 일치).

### 4.4 4단계: 참가자 배정

```bash
cd apps/backend
python scripts/apply_users_to_meetings_accurate.py
```

- **성별 분리 모드** 모임: 남/여 균등 배분으로 필요한 인원만큼 확정 참가자를 채웁니다.
- **성별 혼합 모드** 모임: 인원수만 맞춰 참가자를 채웁니다.
- **주의**: 이 스크립트는 **참가 신청 마감 전**인 모임만 처리합니다. 이미 조기 마감되었거나 마감일이 지난 모임은 건너뜁니다. 따라서 4단계는 **5단계(참가 신청 마감) 전에** 실행해야 합니다.

### 4.5 5단계: 참가 신청 마감

- 각 모임을 "참가 신청 마감" 상태로 만듭니다.
- 방법: 모임별로 **조기 마감** 처리하거나, `application_deadline` 을 과거로 설정해 마감된 것으로 만듭니다.
- 마감된 후에만 "팀 편성 시작"이 가능합니다.

### 4.6 6단계: 팀 편성 실행

- **옵션 A (UI)**  
  모임 상세 → 참가자/진행 상황에서 "팀 편성 시작" → 편성 모드·팀 크기(4) 선택 → "편성 실행" → 미리보기 확인 → "편성 확정". 이를 48개 모임에 대해 반복합니다.
- **옵션 B (API)**  
  - `POST /meetings/{meetingId}/teams/auto-formation` (미리보기용 요청 후, 동일 조건으로 확정까지 진행 가능한 흐름 확인)  
  - `POST /meetings/{meetingId}/teams/confirm`  
  위를 48개 meetingId에 대해 반복하는 스크립트를 작성하면 일괄 실행할 수 있습니다. (문서에는 "선택: API 일괄 실행 스크립트"로 안내)

## 5. PREVIOUS_RECORD 모드용 직전 대회 성적

### 5.1 동작 방식

- `apps/backend/utils/team_formation.py` 의 `sort_by_previous_record()` 는 **MeetingResult** 테이블에서 `user_id` 별로 **가장 최근 `completed_at`** 의 **net_score** 를 조회해, 넷 스코어가 좋은 순(낮은 순)으로 정렬합니다.
- 직전 대회 성적 기준 모드: **D, E, F, M, N, O, 21, 22, 27, 28, 32, 35, 38, 41**.

### 5.2 검증 수준

- **MeetingResult 시드 없이**:  
  - 팀 편성 API는 정상 동작합니다.  
  - 다만 "직전 대회 성적 순 정렬"을 검증하려면 부족합니다. 기록이 없는 참가자는 net_score 999.0으로 처리되어 **마지막에 배치**되는 동작만 확인할 수 있습니다.
- **MeetingResult 시드 있음**:  
  - 참가자(또는 풀 사용자)에게 `MeetingResult` (net_score, completed_at) 를 user별로 1건 이상 넣어 두면, PREVIOUS_RECORD 모드에서 **net_score 좋은 순 정렬 → 지그재그 분배**까지 검증할 수 있습니다.
- (선택) 나중에 **MeetingResult 를 user별로 1건씩 넣는 시드 스크립트**를 만들면, PREVIOUS_RECORD 정렬까지 포함한 전체 검증이 가능합니다.

## 6. 케이스별 검증 포인트

### 6.1 공통

- 확정 참가자 수 = 해당 케이스의 **인원수**.
- 팀 편성 API(미리보기 및 확정) **성공**.
- 생성된 **팀 수** = 예상 팀 수 (위 §2 표의 "예상 팀 구성"에서 팀 개수와 일치).

### 6.2 팀 구성

- **나머지 0**: 모든 팀이 4인조.
- **나머지 1**: 3인조 3팀 또는 3인조 3팀 + 4인조 N팀 (인원수에 따라).
- **나머지 2**: 3인조 2팀 + 4인조 N팀.
- **나머지 3**: 3인조 1팀 + 4인조 N팀.

### 6.3 성별 분리 모드 (GENDER_SEPARATED_*)

- 각 팀 내에 **한 성별만** 포함되는지 확인 (남성 팀 / 여성 팀 완전 분리).
- 남성 팀 수·여성 팀 수와 "성별 분리 시 남/여" 표와 일치하는지 확인.

### 6.4 성별 혼합 모드 (GENDER_MIXED_*)

- 성별을 전혀 고려하지 않고, 전체 인원을 하나의 풀으로 지그재그 분배했는지 확인.
- 팀 내 성별 비율은 제한이 없으며, 우연히 한 성별만 모인 팀이 나와도 동작상 정상입니다.

### 6.5 HANDICAP 모드

- 팀 간 **핸디캡 합계**가 비슷한지 확인 (지그재그로 균등화되는지).

### 6.6 PREVIOUS_RECORD 모드

- MeetingResult 가 있는 경우: **net_score 좋은 순**으로 정렬된 뒤 지그재그 분배되었는지 확인.
- MeetingResult 가 없는 경우: 편성 성공 여부와 "기록 없는 참가자 마지막 배치"만 확인 가능.

### 6.7 RANDOM 모드

- 팀 수·각 팀 인원 수는 위 예상과 동일하고, **순서만 무작위**인지 확인.
